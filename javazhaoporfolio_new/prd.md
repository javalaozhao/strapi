### 1. 目标和背景上下文 (Goals and Background Context)

#### **核心目标 (Goals)**

* 打造一个集个人品牌展示、知识分享与商业变现于一体的高度可拓展平台。

#### **背景上下文 (Background Context)**

本项目旨在创建一个现代化的个人品牌网站。为了实现长期的灵活性和可拓展性，项目将采用 Headless CMS (Strapi) 作为后端，并构建一个独立的、高性能的自定义前端 (Next.js)。项目初期 (MVP) 将聚焦于品牌展示（个人简介、作品集）和基础内容分享（免费博客），以快速建立线上声誉和吸引早期用户。复杂的商业化功能（如付费内容、会员体系）计划在第二阶段引入。

### 2. 需求 (Requirements)

#### **功能性需求 (Functional Requirements)**

* **FR1**: 系统必须提供一个后台界面，允许管理员创建、编辑和发布“个人简介”页面的内容。
* **FR2**: 系统必须提供一个后台界面，允许管理员创建、编辑、删除和发布“作品集/项目集锦”条目，每个条目应包含标题、描述、图片/视频和项目链接。
* **FR3**: 系统必须提供一个后台界面，允许管理员配置和更新“联系方式/社交媒体”的链接列表。
* **FR4**: 系统必须提供一个后台界面，允许管理员撰写、编辑、删除和发布免费的“博客文章”。
* **FR5**: 前端网站必须有一个专门的“关于我”页面，用于展示 FR1 中定义的个人简介内容。
* **FR6**: 前端网站必须有一个“作品集”或“项目”页面，以列表或卡片形式展示所有根据 FR2 发布的项目。
* **FR7**: 前端网站必须在页头或页脚等显著位置展示 FR3 中定义的社交媒体链接。
* **FR8**: 前端网站必须有一个“博客”页面，按时间倒序列出所有根据 FR4 发布的免费文章，并支持点击进入文章详情页。

#### **非功能性需求 (Non-Functional Requirements)**

* **NFR1**: 网站前端界面必须是响应式的，在桌面、平板和移动设备上都应有优美的、现代化的视觉表现和流畅的交互体验。
* **NFR2**: 系统的整体架构必须是模块化和可拓展的，以便在第二阶段能平滑地集成会员、支付等复杂功能。
* **NFR3**: 网站必须对搜索引擎友好 (SEO Friendly)，包括但不限于：生成静态页面 (SSG/ISR)、支持自定义页面的 `meta` 标签、生成 `sitemap.xml`、支持结构化数据 (Schema.org) 和社交媒体分享标签 (Open Graph)。
* **NFR4**: 系统必须支持私有化部署，能够完整地运行在用户自己的服务器上。
* **NFR5**: 系统架构不应与特定云厂商深度绑定，应能兼容部署于中国大陆（如阿里云）和国际（如 Vercel, Google Cloud）的云服务环境。
* **NFR6**: 所有用户上传的图片都应在服务端进行自动化压缩，并尽可能转换为现代化的图片格式（如 WebP），以提升网站加载性能。
* **NFR7**: 系统应集成基础的网站分析工具（如 Vercel Analytics），以便从上线第一天起就开始收集访客数据。

### 3. 用户界面设计目标 (User Interface Design Goals)

#### **整体 UX 愿景 (Overall UX Vision)**

简洁、直观、以内容为中心。用户应能毫不费力地找到他们需要的信息，无论是博文还是项目展示。整体体验应是快速、流畅且令人愉悦的，能有效传递出一种沉静、值得信赖的专业感。

#### **核心交互范式 (Key Interaction Paradigms)**

* **卡片式设计**: 采用现代化的卡片式布局来展示作品集和博客文章，方便用户快速浏览和筛选。
* **响应式布局**: 遵循移动优先原则，确保在从小屏幕到大屏幕的各种设备上都有一致且卓越的浏览体验。
* **微交互**: 通过细腻的悬停效果、平滑的页面过渡动画和即时的加载反馈，提升整体的交互质感。

#### **核心屏幕与视图 (Core Screens and Views)**

* **主页 (Homepage)**: 作为网站的聚合展示，包含精简的个人简介、精选的作品集项目和最新的博客文章。
* **关于我 (About Me)**: 详细的个人介绍页面。
* **作品集 (Portfolio)**: 完整的项目集锦展示页面。
* **博客 (Blog)**: 文章列表及文章详情页。

#### **无障碍设计 (Accessibility)**

* **标准**: 遵循 WCAG 2.1 AA 标准，确保内容对所有用户（包括残障人士）都是可访问的。

#### **品牌与风格指南 (Branding & Style Guide)**

* **核心风格**: **数字花园 & 有机质感 (Digital Garden & Organic Feel)**。
* **色彩搭配**: 以纸张白 (`#FBFBF8`) 为背景，深灰褐 (`#424238`) 为文本，搭配橄榄绿 (`#4A5548`) 和暖橙色 (`#E85D04`) 作为主色和点缀色，营造温暖、自然的视觉感受。
* **字体排印**: 正文使用经典优雅的衬线字体 (如 `Source Serif Pro`)，标题和UI元素使用清晰的无衬线字体 (如 `Inter`)，形成优美对比。

#### **目标设备与平台 (Target Device and Platforms)**

* **平台**: Web Responsive (Web 响应式)，覆盖所有主流浏览器。

### 4. 技术假设 (Technical Assumptions)

#### **后端框架 (Backend Framework)**

* **选择**: Strapi (Node.js / TypeScript)。
* **理由**: 满足对内容模型灵活性的核心需求，拥有成熟的社区和插件生态。

#### **前端框架 (Frontend Framework)**

* **选择**: Next.js (React / TypeScript)。
* **理由**: 提供卓越的性能 (SSG/ISR) 和 SEO 支持，与我们选择的 Shadcn/UI 组件方案完美集成，拥有顶级的开发体验。

#### **数据库 (Database)**

* **建议**: PostgreSQL。
* **理由**: 一款强大的开源关系型数据库，性能稳定，功能丰富，被 Strapi 官方良好支持，能够满足未来的复杂查询需求。

#### **代码仓库结构 (Repository Structure)**

* **建议**: Monorepo (单一代码库)，使用 Turborepo 进行管理。
* **理由**: 将 Strapi 后端和 Next.js 前端放在一个代码库中，便于统一管理依赖、共享代码（如类型定义）和进行集成的自动化部署，非常适合个人或小团队高效开发。

#### **服务架构 (Service Architecture)**

* **设定**: Monolith (单体应用)。
* **理由**: Strapi 本身是一个单体服务。对于当前项目阶段，单体架构最简单、最高效，便于开发和部署。

#### **测试要求 (Testing Requirements)**

* **设定**: 单元测试 + 集成测试 (Unit + Integration)。
* **理由**: 确保核心业务逻辑的正确性，并验证前后端分离接口的稳定性，为项目质量提供坚实保障。

### 5. 史诗与用户故事列表 (Epic & User Story List)

---

#### **史诗 1: 项目基础与博客核心功能 (Project Foundation & Core Blog Functionality)**

**史诗目标**: 本史诗的目标是为项目奠定坚实的技术基础，并交付网站的第一个核心价值功能——一个完整的博客系统。完成此史诗后，我们将拥有一个可运行、可部署的全栈应用，并能够通过后台管理和发布文章。

**用户故事 (User Stories):**

**故事 1.1: 项目初始化与 Monorepo 环境搭建**
* **As a** 开发人员,
* **I want** 一个配置好的、包含 Strapi 后端和 Next.js 前端项目的 Monorepo 环境,
* **so that** 我可以在一个干净、一致的环境中开始高效开发。
* **验收标准**:
    1.  一个新的 Git 代码仓库被创建。
    2.  使用 `Turborepo` 初始化 Monorepo 结构。
    3.  一个 Strapi 项目在 `apps/api` 目录中被成功创建。
    4.  一个 Next.js 项目（集成 TypeScript 和 Tailwind CSS）在 `apps/web` 目录中被成功创建。
    5.  可以成功地通过一个命令 (如 `npm run dev`) 同时启动前后端两个服务。
    6.  基础的网站分析工具（Vercel Analytics）被集成到 Next.js 应用中。

**故事 1.2: 配置文件存储服务**
* **As a** 开发人员,
* **I want** 将 Strapi 的媒体库配置为使用 Cloudflare R2 进行文件存储,
* **so that** 所有上传的图片都能被高效、可靠地托管。
* **验收标准**:
    1.  Strapi 的文件上传功能已正确配置为使用 Cloudflare R2 插件。
    2.  在 Strapi 后台上传一张图片，该图片被成功存储到指定的 R2 存储桶中。
    3.  Strapi 返回该图片的公开访问 URL。

**故事 1.3: 创建 Strapi 文章内容模型**
* **As an** 网站管理员,
* **I want** 在 Strapi 后台中拥有一个包含分类和标签的“文章 (Article)”内容类型,
* **so that** 我可以更好地组织和管理我的博客文章。
* **验收标准**:
    1.  在 Strapi 后台，创建名为 “Article”, “Category” (分类), 和 “Tag” (标签) 的三个新的集合类型。
    2.  “Article” 类型包含以下字段：`title`, `content`, `slug`, `cover_image`，以及 `category` (与 Category 的一对一关系) 和 `tags` (与 Tag 的多对多关系)。
    3.  “Category” 和 “Tag” 类型至少包含一个 `name` (名称) 字段。
    4.  所有三个内容类型的 API 权限被设置为允许公众匿名读取。
    5.  我可以在 Strapi 管理界面中成功创建一篇文章，并为其关联一个分类和多个标签。

**故事 1.4: 展示博客文章列表页面**
* **As a** 网站访客,
* **I want** 看到一个支持分页、信息清晰的文章列表页面,
* **so that** 我可以高效地发现和浏览网站的海量内容。
* **验收标准**:
    1.  在前端网站中，一个新的页面被创建，路径为 `/blog`。
    2.  每篇文章在列表中以卡片形式展示，至少包含封面图、标题、发布日期和所属分类。
    3.  列表必须支持分页，每页最多显示 10 篇文章，并提供清晰的“上一页/下一页”导航。
    4.  点击任意文章卡片，页面会跳转到该文章的详情页。
    5.  在数据加载过程中，页面会显示一个加载状态。

**故事 1.5: 展示博客文章详情页面**
* **As a** 网站访客,
* **I want** 查看单篇博客文章的完整内容及其分类和标签,
* **so that** 我可以进行深度阅读并发现相关内容。
* **验收标准**:
    1.  在前端网站中，一个新的动态路由页面被创建，路径为 `/blog/[slug]`。
    2.  页面清晰地展示文章的标题、封面图、完整的正文内容，以及其所属的分类和所有标签。
    3.  如果根据 `slug` 未找到文章，页面应显示 404 Not Found 错误。

#### **史诗 2: 个人品牌展示与网站完善 (Personal Brand Showcase & Site Polishing)**

**史诗目标**: 本史诗的目标是在已有的博客系统基础上，全面构建你的个人品牌展示模块，并对网站进行整体的完善和收尾工作。完成此史诗后，MVP 阶段的所有核心功能将全部上线，网站将成为一个功能完整、体验统一的个人品牌平台。

**用户故事 (User Stories):**

**故事 2.1: 创建 Strapi 品牌内容模型**
* **As an** 网站管理员,
* **I want** 在 Strapi 后台为“作品集”、“关于我”和“社交链接”创建对应的内容类型,
* **so that** 我可以集中管理所有与个人品牌相关的网站内容。
* **验收标准**:
    1.  创建一个新的 “Technology” (技术) 集合类型。
    2.  创建一个新的 “Portfolio Item” (作品集条目) 集合类型，并建立与 “Technology” 的多对多关系。
    3.  创建一个新的 “About Page” (关于页面) **单一类型**。
    4.  创建一个新的 “Social Link” (社交链接) 集合类型，其“平台”字段为预设的枚举选项。
    5.  所有新内容类型的 API 权限均设置为允许公众匿名读取。

**故事 2.2: 展示作品集/项目页面**
* **As a** 网站访客,
* **I want** 访问一个专门的“作品集”页面来查看你的所有项目,
* **so that** 我可以快速了解你的专业技能和项目经验。
* **验收标准**:
    1.  在前端网站中，一个新的页面被创建，路径为 `/portfolio`。
    2.  此页面会从 Strapi API 获取所有“Portfolio Item”数据。
    3.  每个项目都以卡片形式展示，包含图片、标题、描述和所用技术。
    4.  点击项目的外部链接，可以在新标签页中打开对应的项目地址。

**故事 2.3: 展示“关于我”页面**
* **As a** 网站访客,
* **I want** 访问一个“关于我”页面,
* **so that** 我可以更深入地了解你的背景和经历。
* **验收标准**:
    1.  在前端网站中，一个新的页面被创建，路径为 `/about`。
    2.  此页面会从 Strapi API 获取“About Page”的数据并完整展示其内容。
